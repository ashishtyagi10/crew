# Loop — thirteen crew, thirteen UI and thirteen smith rounds

**Status: IN PROGRESS** (thirty-nine rounds, one release each, after v0.29.62). Set by the user
on 2026-11-04: *"run crew, ui and smith loop 13 times each and release after each
iteration"*.

## Rules that hold every round

The rules of the [loop before it](2026-11-02-loop-8.md) carry over: one round, one release;
the lanes take turns (crew, UI, smith, then again); a test fails without each fix; every
`.rs` file stays under the 200-line cap; the release log is read for `RELEASED` before the
next round starts, and the Release, Windows and Coverage runs are read after.

This loop runs in the main checkout. `scripts/release.sh` ships the uncommitted edits on
`main`, so nothing is edited while a gate runs, and only one round is open at a time.

## The survey (once, for all thirty-nine rounds)

Three at once, one per lane, each starting from the last loop's `## Close`: what is still
real in the code, plus what is new. Each lane keeps a ranked queue of at least thirteen.

## Log

**Round C1 (v0.29.63): reverse video draws its bars on the alternate screen.**

- **The survey** found `modelcells.rs` ignoring SGR 7 on every screen, on purpose for the
  line agent CLIs echo, so vim's status line, nano's bars and less's prompt were plain text.
  The reversed blanks that make a bar were dropped as empty cells, and a swapped grey would
  have been flattened by the echo-grey drop. Measured in a real pty: `less` enters `?1049h`
  and draws `\e[7mf.txt (END)\e[27m`.
- **Now** `modelinverse.rs` swaps fg and bg when the alternate screen is up, and a swapped
  cell skips the echo-grey drop. The primary-screen rule stays. Three tests in
  `modelinverse_tests.rs`: a bar with its two reversed spaces drawn, the bar's grey kept, and
  plain reverse video back on the primary screen. The first two fail with the swap removed,
  and again with only the drop guard removed. `modelcells.rs` went from 229 to 228 lines.

**Round U1: the narrow theme picker keeps its descriptions.**

- **The survey** found `/theme` at a quarter tile (380 px, 40 columns of row) cutting every
  description to about seven letters (`black…`, `rotatin…`, `every…`). The swatch column is
  the list's widest swatch, `auto`'s fifteen-chip strip, and every row reserved it, the
  one-chip rows included, which left each description ten columns.
- **Now** `swatchfit.rs` caps the column at what leaves the description sixteen columns, and
  `cmdrow::spans` cuts a longer strip to the column instead of letting it push its
  description out. At 40 columns `auto` shows seven chips, the palettes keep all six, and the
  rows read `black page…`, `rotating CRT…`, `every look in…`. A wide card keeps the whole
  strip. Three tests in `swatchfit_tests.rs`: every row keeps its first word whole with at
  least sixteen columns of room, a wide list keeps the full column, and `auto`'s description
  starts where `dark`'s does. The first fails with the cap removed, and the first and third
  fail with only the strip cut removed. Shots: `pick-theme-narrow.png` before and after.
