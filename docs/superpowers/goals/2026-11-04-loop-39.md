# Loop — thirteen crew, thirteen UI and thirteen smith rounds

**Status: IN PROGRESS** (thirty-nine rounds, one release each, after v0.29.62). Set by the user
on 2026-11-04: *"run crew, ui and smith loop 13 times each and release after each
iteration"*.

## Rules that hold every round

The rules of the [loop before it](2026-11-02-loop-8.md) carry over: one round, one release;
the lanes take turns (crew, UI, smith, then again); a test fails without each fix; every
`.rs` file stays under the 200-line cap; the release log is read for `RELEASED` before the
next round starts, and the Release, Windows and Coverage runs are read after.

This loop runs in the main checkout. `scripts/release.sh` ships the uncommitted edits on
`main`, so nothing is edited while a gate runs, and only one round is open at a time.

## The survey (once, for all thirty-nine rounds)

Three at once, one per lane, each starting from the last loop's closing list: what is still
real in the code, plus what is new. Each lane keeps a ranked queue of at least thirteen.

- **The survey** found no answer to XTVERSION, `CSI > q` / `CSI > 0 q`: vte 0.15 has no arm for
  it and no crew scanner looked for it. Over ssh or inside tmux `TERM_PROGRAM` never reaches the
  program, and XTVERSION is how neovim, yazi, fzf's previews, notcurses and the kitty-graphics
  probes recognise the terminal. Measured on a real pty (`sh`, `stty -icanon time 20`, then
  `printf '\033[>0q'` and `dd` the reply): nothing came back in two seconds.
- **Now** the `CSI 16 t` scanner moved out of `modelsize.rs` (80 → 55 lines) into a new
  `modelquery.rs` (59) that answers both, so `model.rs` did not grow. XTVERSION answers
  `DCS > | crew <version> ST`, as xterm, kitty and WezTerm do; the same pty probe now reads
  `ESC P>|crew 0.29.80 ESC \`. `modelquery_tests` pin both spellings through a HeadlessTerm,
  the query split byte by byte across reads, near misses staying silent (DA2 `> c`, XTMODKEYS,
  DECSCUSR `1 SP q`, `> 1 q`) and replies in the order asked; three of the four fail with the
  XTVERSION arm disabled. docs/CREW.md says so beside `TERM_PROGRAM`. #8 (pictures leave with
  `clear` and the alternate screen) was not paired: it reaches into the app's picture layer and
  needs its own shots.
