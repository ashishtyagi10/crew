# Loop — thirteen crew, thirteen UI and thirteen smith rounds

**Status: IN PROGRESS** (thirty-nine rounds, one release each, after v0.29.62). Set by the user
on 2026-11-04: *"run crew, ui and smith loop 13 times each and release after each
iteration"*.

## Rules that hold every round

The rules of the [loop before it](2026-11-02-loop-8.md) carry over: one round, one release;
the lanes take turns (crew, UI, smith, then again); a test fails without each fix; every
`.rs` file stays under the 200-line cap; the release log is read for `RELEASED` before the
next round starts, and the Release, Windows and Coverage runs are read after.

This loop runs in the main checkout. `scripts/release.sh` ships the uncommitted edits on
`main`, so nothing is edited while a gate runs, and only one round is open at a time.

## The survey (once, for all thirty-nine rounds)

Three at once, one per lane, each starting from the last loop's closing list: what is still
real in the code, plus what is new. Each lane keeps a ranked queue of at least thirteen.

**Round U2 (v0.29.67): a diff's last number is the hunk's last line.**

**Round C3 (v0.29.69): Ctrl+Space, Ctrl+/ and Ctrl+2…8 send their control bytes.**

- **The survey** found three chords typing the wrong thing in a terminal pane. winit names
  Space (`NamedKey::Space`), so `session::named_bytes` sent a plain space for Ctrl+Space and
  the Ctrl+letter table never saw it: emacs/readline set-mark and a C-Space tmux prefix were
  dead. `ctrl_byte` only mapped `'@'..='_'`, so Ctrl+/ sent `/` (xterm: 0x1f, emacs/nano undo)
  and Ctrl+2…8 sent the bare digit (xterm: NUL, ESC, FS, GS, RS, US, DEL).
- **Now** `keyenc::named` answers Ctrl+Space with NUL, and `session::ctrl_byte` follows
  xterm's digit and slash table; Ctrl+1, 9 and 0 still send the digit. `keyenc_tests.rs`
  pins Ctrl+Space → `[0]` and plain Space left to the table; `session_tests.rs` pins the
  seven digits and `/`. Both fail with the two new arms disabled. Off a Mac, Ctrl+digit and
  Ctrl+/ stay crew's Cmd stand-ins (`keychord::plain`), as before; Ctrl+Space reaches the
  program there too. A pure encoder change, not driven live.

**Round C4: mouse clicks reach programs that asked for them.**

- **The survey** found only the wheel ever reported to a program (`altscroll::mouse_tick`):
  no `ESC[<0;x;yM` was written anywhere, so a left press in htop, mc, lazygit, tmux or vim

- **Now** `mousereport.rs` encodes a press or release (SGR `ESC[<b;x;yM`/`m`, legacy X10 with

  any mouse mode on and Shift not held. `mouseroute.rs` sends the press at the cell under the
  pointer (inside the grid only) for left, middle and right, holds it, and sends the release
  to the same pane; `events.rs` checks it after crew's own targets (toasts, nav edge, gutter,
  docked buttons, legend row), and right-click pastes only where no program asked. The
  resize and scale bodies moved to `winresize.rs`, so `events.rs` went from 298 to 292
  lines. `mouseroute_tests.rs` drives a real pty whose program copies its raw stdin to a
  file: a click on content cell (4, 2) after `ESC[?1000h ESC[?1006h` arrives as
  `ESC[<0;5;3M ESC[<0;5;3m`, and fails with the routing disabled; Shift, or a program with
