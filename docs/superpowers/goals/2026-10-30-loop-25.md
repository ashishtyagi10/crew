# Loop — five AI, five UI, five crew, five smith and five inbox rounds

**Status: IN PROGRESS.** Set by the user on 2026-10-30, after the theme loop: *"run ai
enhancement, ui enhancement, crew enhancement, smith enhancement and inbox enhancement loop 5
times each and release after each version"*.

## Rules that hold every round

- **One round, one release.** Each ships through `scripts/release.sh` (it picks the version,
  gates `crew-app` plus the crates in `EXTRA`, merges `--no-ff`, tags and pushes main and the
  tag together). The lanes take turns — AI, UI, crew, smith, inbox — so no lane waits on
  another, and only one release runs at a time.
- **AI** rounds follow `/improve` (`.superpowers/sdd/ai-loop-2026-09-14.md`): one harness
  feature, the smallest honest version, the changelog naming the tool the idea came from, and
  "unit tests only" said plainly where no live probe reaches it.
- **UI** rounds follow a shot survey: layout, spacing, clipping and legibility rather than more
  palette work (the theme loop just ended). Nothing new on screen without a shot.
- **Crew** rounds follow `/crew`: the terminal and the panes — escape sequences, selection,
  scrollback, the multiplexer — never an overlay, never a layout switcher, keys pass through.
- **Smith** rounds follow `/smith-loop` (`.superpowers/sdd/smith-loop-2026-10-16.md`): depth,
  trustworthy feedback, drawn marks that carry information, and a bloat budget.
- **Inbox** rounds follow the inbox loops' rules: a round fixes, simplifies or polishes; nothing
  a test does opens a browser or reads the real grant, Downloads or Reminders.
- Every file stays under the 200-line cap and no file in `line-cap-debt.txt` grows; a test
  fails without each fix; no scratch file stays in the tree while `release.sh` runs (it commits
  with `git add -A`); its log is read for `RELEASED` before the next round starts, and the
  Windows and Coverage runs are read after.

## The survey (once, for all twenty-five rounds)

Five at once, one per lane, each a ranked list of release-sized gaps with file and line.

## Log

**Round S1 (v0.29.29): a Claude Code reply counts its whole prompt.**

- **The survey** found the relay's trailer reading "2 in": `claudestream.rs` took the
  `result` line's `input_tokens`, which on Anthropic is the uncached remainder only.
- **Measured** on a live `claude -p` run (a Read, then the answer): the result usage is
  summed over both calls (4 uncached, 19,113 written, 41,326 read) and `iterations` holds the
  last call (2 + 319 + 30,060). The count now takes that last prompt whole, through the API
  path's own `anthropic_input` — 4 → 30,381.

**Round A1 (v0.29.30): Esc stops Claude Code where it stands.**

- **The survey** found the relay's read loop (`claudeagent.rs`, and `run.rs` for codex and
  opencode) watching only its idle deadline. The dial blocks its thread, so the harness's
  race against the stop never reached it, and Claude Code went on editing after Esc.
- **Measured:** TERM (or INT) to a live `claude -p` that was running `sleep 47` through its
  Bash tool ended the sleep and the CLI within three seconds. `clistop.rs` sends TERM, then
  KILL after two seconds. The CLI stays in the broker's process group, because closing a
  pane kills that group.
- **Proof:** fake CLIs that sleep for 30 s end within half a second of the stop, on both
  loops. A dial that ends on the stop ends the turn stopped; with the harness guard removed,
  that test fails. The broker was not driven end to end.

**Round U1 (v0.29.31): the selected email's highlight keeps air at both ends.**

- **The survey** (64 shot tests across palettes) ranked first the inbox selection. The time
  touched the wash's right edge, and the wash stopped a column short of the box on the right
  but not on the left (`row.rs` drew `cols - 1` columns).
- **Now** the wash spans the list and the text ends two columns short. Shots on paper-light
  and glass-night, in the list and the split view, show the wash inset evenly on both sides.

**Round C1 (v0.29.32): programs in a pane know they run in crew.**

- **The survey** found `ptyspawn.rs` setting only `TERM` and `COLORFGBG`. No `COLORTERM` from
  a Dock launch (chalk drops to 256 colours), and another terminal's `TERM_PROGRAM`, kitty or
  tmux variables leaked into every pane from a launch inside one.
- **Now** `ptyident.rs` names crew with 24-bit colour and drops 28 foreign names. A real `sh`
  in a pty prints `truecolor` and `crew`.

**Round S2 (v0.29.33): smith's proof says how many tests ran.**

- **The survey** found `chatproof.rs` keeping only the exit status of the last test run. A
  `cargo test <filter>` that matched nothing exits 0 and read "✓ checked".
- **Now** `testtally.rs` reads the runner's summary (cargo summed over binaries, with failing
  names; pytest; jest and vitest). The count sits right after the command: the first shot put
  it at the end, and the folded receipt cut it at half width. A run of no tests is
  "! not checked". The proof shot covers paper-light and glass-night at 470 and 700 px.

**Round I1 (v0.29.34): new mail shows after paging; a failed list is never inbox zero.**

- **The survey** found `workerlist.rs` storing the mailbox's history id on every list: on a
  further page (`j`) and before a page that went on to fail. The minute's check then said
  "nothing moved" against a page the pane never had.
- **Now** only a first page that came back sets it, and a failed one clears it. Both tests
  fail with their half of the fix taken out.

**Round A2 (v0.29.35): Claude Code starts on a message with no skill pick in front of it.**

- **The survey** found the relay running the skill decider before every hop. Signed in to
  Claude Code, that decider is a second `claude -p`. Measured 4.6–7.0 s wall per message,
  and `--effort low` was no faster because the CLI's start dominates.
- **Now** agents that read files themselves get the catalog (`skillcatalog.rs`, 3.4 KB for
  17 skills) and choose within their own turn, as Claude Code's skills do. Live: a PDF task
  read `pdf/SKILL.md` first, and a question about a file read no skill.
- **Not done:** the survey's #2. The docs name `~/.config/crew` for `mcp.json`, `hooks.json`
  and `memory.md`, but macOS reads `~/Library/Application Support/crew`. Reading both would
  start the dormant `fs` MCP server in this user's `~/.config/crew/mcp.json`, so that is
  left for the user to decide.

**Round U2 (v0.29.36): the row you're on in a picker is highlighted.**

- **The survey's #2 and #3:** pickers marked the selection with `›` and bold alone, which was
  faint on CRT and confusable with the bold section titles. The no-match note sat against the
  card's edge.
- **Now** `menuwash.rs` washes the selected row edge to edge, lifting its colours and
  leaving match chips and swatches their own ground. The old no-bar test came from a June
  technical reason that no longer holds, and now pins one wash on the selected row. The note
  keeps the marker's columns. Shots: palette on CRT and light, model picker, theme picker
  with swatches, no-match note.

**Round C2 (v0.29.37): Option+arrows jump a word; F1–F12 reach the program.**

- **The survey** found `session.rs` with no function keys and no Alt, and DECCKM ignored for
  keys.
- **Measured first**, typing into a bare zsh and bash through a pty: `ESC b` and `ESC DEL`
  move back and delete a word. The xterm-modified arrows (`ESC [1;2D`, `;5D`, `;3D`) were
  swallowed along with the next key, so Shift and Ctrl arrows stay plain. `keyenc.rs` sends
  the word keys, xterm's function keys with modifiers, and application-mode cursor keys.

**Round I2 (v0.29.38): mail from Apple Mail shows what comes after an attachment.**

- **The survey** found `body.rs` taking the first html part, and Apple Mail splits the html
  around a file placed in the text. Everything after an inline PDF was lost, including in
  forwards and in what smith read.
- **Now** the pieces of a `multipart/mixed` are joined in order and named files are never
  joined. The Apple-shaped test fails with the join taken out.

**Round S3 (v0.29.39): a live tool block folds to the last three calls.**

- **The survey's #2 and #5:** a live block drew a row per call (a thirty-row wall on a long
  relay turn), and the code line dimmed as stalled during every silent tool run.
- **Now** `chattoolwindow.rs` heads a live block of more than four calls with a count that
  opens on a click. Drawing and click mapping walk the same fold. A running tool isn't a
  stall: the dimming test fails with the guard removed. The shot shows nine folded
  calls with one failure, then Grep, Edit and a running Bash.
