# Loop — two AI, two UI, two smith and two crew rounds

**Status: DONE** (eight rounds, one release each, from v0.29.51). Set by the user on 2026-11-02: *"Run the AI, UI, Smith and Crew loop 2
time each and release after each iteration"*.

## Rules that hold every round

The rules of the [loop before it](2026-10-30-loop-25.md) carry over unchanged: one round, one
release; the lanes take turns (AI, UI, smith, crew, then again); a test fails without each fix;
every file stays under the 200-line cap and no file in `line-cap-debt.txt` grows; the release
log is read for `RELEASED` before the next round starts, and the Windows and Coverage runs are
read after.

This loop runs from a worktree while `main` is checked out in the main clone, so each release
goes through a copy of `scripts/release.sh` that merges onto `origin/main` detached and pushes
`HEAD:main` with the tag.

## The survey (once, for all eight rounds)

Four at once, one per lane, each starting from the last loop's survey: what is still real in
the code, plus what is new.

## Log

**Round S1 (v0.29.51): smith's "✓ checked" means a real run after the last edit.**

- **The survey** found `chatproof.rs` matching words anywhere in a command, so
  `wc -l src/x_tests.rs` stood in for a failing `cargo test` and the turn read ✓. A
  background run read as passed, and a green lint after a red test erased the red.
- **Now** `chatproofcmd.rs` judges each piece of a command by its program, edits through
  the shell (`sed -i`, `cargo fmt`, `git apply`, `> file`) count as edits, a background run
  stays pending, and only the same command again clears a failure. Five of the six new tests
  fail on the old proof. Tests only: the verdict's wording is unchanged, so no new shot.

**Round A1 (v0.29.52): when Claude Code isn't allowed a tool, crew names it.**

- **The survey** found `claudestream.rs` never reading the result line's
  `permission_denials`. In print mode a tool the settings don't allow is refused and the run
  goes on. Measured: a write and two commands were refused, and the reply said only that
  they "needed approval".
- **Now** `clauderesult.rs` folds the list into one line under the reply: what was refused,
  and where to allow it. Live through the real broker in a folder set to default mode, the
  note came out under the reply. The same run showed Claude Code, blocked, writing crew's
  own `@tool sys:write_file` syntax into its answer, which the turn did not run. That is
  left for a later round.

**Round C1 (v0.29.53): a paste into a program that isn't reading no longer freezes crew.**

- **The survey** found every pane write (keys, paste, query replies) blocking on the
  window's thread. Measured: 4 KiB into `stty raw -echo; sleep 4` waited 3.8 s, then failed.
- **Now** `ptywrite.rs` gives each pane a writer thread fed by a queue in send order. The
  64 KiB test returns in under half a second, and fails on the old writer (it waits until
  the child dies). A second test pins the order of interleaved writes from two handles.

**Round A2 (v0.29.54): a timed-out agent CLI ends its own commands first.**

- **The survey** found the relay's idle timeout and `run_cli`'s deadline sending KILL
  straight away. The stop has sent TERM first since A1 of the last loop, because Claude Code
  ends its Bash children on TERM.
- **Now** both go through `clistop::ended`. A fake that traps TERM leaves its mark on both
  paths. With the old kill it leaves none, and the test fails.

**Round U1 (v0.29.55): a picker's highlight meets both strokes; the font list has one.**

- **The survey** (85 shot tests across six palettes) found the pickers' wash only as wide as
  the rows' measure: it ended 2 columns short of the right stroke, and about 10 in `/todo`'s
  `@project` pop-up. The settings font list still marked its cursor with `›` and bold alone,
  like the bold current family.
- **Now** `cmdmenu` washes the list's full interior and the dropdown's cursor takes the
  same wash. Both tests fail with their fix out. Shots: palette, `@project` pop-up, font
  list.

**Round S2 (v0.29.56): the "still working" note goes when the turn does.**

- **The survey's #2** (the context gauge on the Claude Code relay) was set aside: the
  model has to be re-sent in the roster from `stdio.rs` (800 lines), and the broker
  rebuilds its registry on every message. Its runner-up went in instead. The 90 s quiet
  note became a card, another every three minutes, and stayed under the finished answer.
- **Now** one quiet note is live at a time and the turn's end removes it. The watchdog test
  fails with the removal taken out.
- **A near miss:** these edits were made while U1's gate ran, and its `git add -A` swept
  them in. The commit hook's format check failed and stopped it before anything was
  committed or pushed. U1 was re-run on its own files. Nothing is edited during a gate.

**Round C2 (v0.29.57): panes speak UTF-8 when crew starts from the Dock.**

- **The survey** found nothing setting a locale for a pane. On this machine the Dock-launched
  crew has none, and `~/.zshrc` has its `export LANG` commented out. Measured in a tty with
  none: `caf??.txt`, `é` counted as two characters, `locale charmap` US-ASCII.
- **Now** `ptylocale.rs` sets `LANG` from macOS's language as a UTF-8 locale when the pane has
  no `LANG`, `LC_ALL` or `LC_CTYPE`. Through a real pty with no locale, `locale charmap`
  reads UTF-8, and US-ASCII with the call removed. The gate's own environment has a `LANG`,
  so in CI that test passes either way. The unit tests on `settle` don't depend on it.

**Round U2: a new pane's footer shows only what it knows.**

- **The survey's #1** (the last loop's #8, never shipped; on 14 of 85 shots): a pane that
