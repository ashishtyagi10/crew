# Goal — a Todo pane: capture, done, delete, due dates and @projects while typing

**Status: IMPLEMENTED 2026-08-09** (same day) — all seven contract items landed on `main`
(`crew-app/src/todopane/`, 49 unit tests + 3-mutation spot-check; the overdue/upcoming rank
split proved redundant — due-ascending already orders it — and was simplified out). **Live
verify is still pending:** the GUI harness was blocked mid-run by macOS permissions
(screencapture denied, partial AX) and focus contention with the user's live crew session —
worth a pass when a display is free: type `pay rent tomorrow 5pm @home`, watch the tint +
`due …` legend, Enter, toggle by mouse, restart, catch a due toast.

**Set:** 2026-08-09 by the user: crew gets a `/todo` pane that maintains a todo list. Typing
creates an item; items can be marked done, deleted, and edited in place. Due dates are set by
just typing them ("pay rent tomorrow", "ship build fri 5pm") — the pane recognizes the date
fragment live and strips it from the title on save. Projects are set while typing with `@`
(`@crew fix scroll drift`) — free-form tags, created on first use, autocompleted from tags used
before. One global list, same from every window, filterable by project.

## Decisions already made (asked and answered)

- **Due dates: natural language, no sigil.** The composer live-highlights the recognized date
  fragment; on save it becomes the item's `due` and leaves the title.
- **`@project` = free-form tag.** First use creates it; autocomplete suggests previously used
  tags. Purely a grouping label inside the todo store — not tied to workspace dirs.
- **One global store.** Lives next to config in `dirs::config_dir()/crew/`, survives restarts,
  shared by every pane and window.
- **In scope for v1 (not stretch):** overdue emphasis + sort, edit in place, and a toast when an
  item comes due while crew is running.

## What already exists (the pane is assembly, not invention)

- **Pane plumbing is a known recipe.** `PaneContent` enum (`crew-app/src/pane.rs:37`), slash
  dispatch in `dispatch.rs::run_slash_command` + palette row in `cmddefs/look.rs`, spawn
  shape in `spawn.rs::spawn_settings_pane` (push + `focus_new_pane()`), render entry
  `Pane::cells`, key routing in `keys.rs` (pane returns an action enum, app applies it), plus the
  ~10 small match arms (`poll.rs`, `scroll.rs`, `windowtitle.rs`, `panes_roster.rs`,
  `sessionrestore.rs`, `clipboard.rs`/`filedrop.rs` no-ops). `/view` and `/far` are the
  worked examples.
- **Inline composer + @-completion machinery.** The chat pane already owns a pane-local
  fieldset composer (`chatinput.rs`, keys in `chatkeys.rs`) — required here, since the docked
  input bar intercepts all keys when focused. `chatmention.rs` is the whole @-mention engine
  (`pending_mention`, ranked `filter`, `accept` splice-back, `MentionState`, `spans` for chip
  tinting) and generalizes to `@project` by feeding it a tag entry list instead of agents/files.
- **Selectable list rendering + row hit-testing.** `cmdmenu.rs` (ratatui List → `CellView`) and
  `farpane/render.rs` are the row-list precedents; `settingspane/form.rs` shows checkboxes and a
  per-field rect table. Mouse: `openurl.rs::cursor_rowcol` is the shared pixel→content-cell math,
  `chatfold.rs` is the arm-on-press / fire-on-release pattern a checkbox click wants, and
  `clickopen.rs::view_link_at` is the pure scroll-aware (row,col)→item mapping to copy.
- **Persistence precedents.** `session.toml` (serde TOML, rewrite-on-save, open `kind` strings
  for forward compat) and `usage.jsonl` (append-only, serde-default rule). Checkbox glyphs exist
  in `md/tasklist.rs`.
- **Toasts + cheap clocks.** `toast.rs::Toasts::push(text, legend, alert, now)`; the 16 ms poll
  loop with opt-in redraw, the `fontrotate.rs` 10-minute clock and the ~1 Hz `blocked.rs::due`
  throttle are the precedents for a periodic due-check with **zero per-frame work**.
- **What does NOT exist: natural-language date parsing.** chrono 0.4 is a workspace dep, but no
  NL date crate is anywhere in the lock file.

## The contract (definition of done)

1. **`/todo` opens the pane; typing captures.** A bordered fieldset pane (no title bar — legend
   on the border, house style) with its own inline composer. Enter on non-empty text creates an
   item; the list renders newest-relevant-first (see 5). New pane kind `PaneContent::Todo`,
   `/todo` in `COMMANDS` and `run_slash_command`, session save/restore as kind `"todo"`.
2. **Due date recognized while typing.** A small, hand-rolled, bounded parser module (own file,
   unit-tested; no god object) over an explicit grammar: `today`, `tomorrow`, weekday names
   (short/long, next occurrence), `in N days/weeks`, `MMM D`/`D MMM`, `YYYY-MM-DD`, optional
   `H[:MM] am/pm` / `HH:MM`. The recognized fragment is tinted in the composer as you type
   (chip-tint via the `spans` pattern) so acceptance is visible *before* Enter; on save it is
   stripped from the title and stored as the due timestamp. Unrecognized words are never eaten —
   when in doubt, it's title text. No new dependency unless the hand-rolled grammar proves
   insufficient in practice.
3. **`@project` completes while typing.** `@` mid-composition pops the mention menu fed by the
   distinct tags already in the store (ranked filter, `MAX_MATCHES` cap); any new word after `@`
   is accepted as a new tag. Stored per item; the tag renders as a tinted chip in the row. A
   filter affordance (e.g. typing `@tag` alone, or a key) narrows the list to one project;
   empty filter shows all.
4. **Done, delete, edit — keyboard and mouse.** Up/Down move a selection cursor between the
   composer and rows (Tab toggles focus zones); Space/Enter on a row toggles done;
   Backspace/Delete (or `d`) deletes with no confirm dialog — deletion is small and the store
   rewrite makes it cheap, but the row must visibly leave. Clicking the checkbox cell toggles
   done (press/release arm pattern); an `[x]` affordance at row end deletes. `e` (or Enter on a
   selected row? — pick one, document it) reloads the item into the composer for in-place edit
   of title/due/@project; saving replaces the item, Esc cancels.
5. **Overdue emphasis and honest ordering.** Sort: overdue first (warn/accent tint), then due
   ascending, then undated by creation, done items sink to the bottom dimmed. Ordering is a pure
   function with unit tests. Contrast obeys the theme's `contrast_thresholds` — no hardcoded
   colors, works across all four themes.
6. **Due toast, idle-safe.** A due-check runs on a coarse clock (~1 min granularity, the
   `blocked.rs::due` throttle shape) inside `poll_panes`; when an item's due time passes while
   crew runs, fire one toast (legend `"due"`) — once per item, marked notified in the store so a
   restart doesn't re-toast the backlog. `wants_animation_frame` gains **no new term**: a resting
   todo pane requests no frames; only live toast slide/fades animate (already covered by
   `Toasts::any_live`).
7. **One global store, off-thread-safe writes.** `todos.toml` in `dirs::config_dir()/crew/`
   (serde, rewrite-on-save like `session.toml`; every future field ships with
   `#[serde(default)]`). Load once at pane open on a worker thread if file size warrants it
   (`viewpane/load.rs::start` channel pattern), saves are small synchronous writes (the
   `CrewConfig::save` precedent) debounced to at most one write per user action. Two windows
   editing simultaneously is out of scope for v1 — last write wins, documented in the module doc.

## Stretch (ranked, separate iterations)

1. **Recurring items** — "every mon", "daily"; done re-arms the next occurrence.
2. **`crew todo add …` CLI/IPC** — capture from any terminal via the existing panes-roster IPC
   path; sentinel-network flavored later.
3. **Cross-instance sync** — the store is a natural first shared document for the sentinel
   network vision; explicitly not now.
4. **Smith integration** — `/smith` can read/append todos as task outputs.
