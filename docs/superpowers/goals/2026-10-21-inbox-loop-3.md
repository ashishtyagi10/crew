# Loop — the inbox, a third five rounds

**Status: IN PROGRESS.** Set 2026-10-21 by the user, right after the second loop closed
(`2026-10-21-inbox-loop-2.md`): *"run the inbox enhancement loop 5 more times"*.

## Rules that hold every round

The second loop's rules, which the user set and which still hold:

- No feature the user did not ask for. A round fixes, simplifies or polishes what is there.
- `r` replies to everyone on the mail; there is no other reply, and no Bcc.
- The list, the open mail and the reply box are each a card, and the mail's card is always
  taller than the reply box.
- Every surface is judged on both pages (the Ink Reader light page and glass), every file
  stays under the 200-line cap, the foot keeps every key visible, and nothing is fetched
  that was not fetched before.
- No scratch file stays in the tree while `scripts/release.sh` runs (it commits everything).

## One round

1. **Survey** a state the earlier rounds did not look at, as text dumps of the pane at a few
   sizes (fast, exact) and as shots on both pages (`inboxreadshot_tests`,
   `inboxsplitshot_tests`, `inboxmailshot_tests`).
2. **Pick** the two to four fixes a reader would notice most, none of them a new feature.
3. **Build** them with tests, look again, release, and log the round below.

## Log

**Round 1 (v0.27.63): the setup page, and a mail's files.**

- **The survey** (text dumps of a loading thread, a thread of four with a quote and a file,
  `q`, `x`, `u`, a note in the foot, a 44-column list, the setup page). The setup page still
  opened with "Gmail in this pane, read-only", true until v0.27.30, and it and the sign-in
  page were the only surfaces of the pane with no card. A mail's file row hung off whatever
  came last: under a folded quote it read as part of the fold, and with `q` it sat on the
  last quoted line.
- **The setup and sign-in pages are cards** (`set up Gmail`, `signing in`) like the rest, and
  the setup page says the pane reads, files and replies (`crates/crew-app/src/inbox/setup.rs`).
- **A row of air above a mail's files** (`readmail.rs`), so they read as the mail's.
- **Tests:** the setup page is a card that no longer says read-only; a file row stands apart
  from the quote above it.

**Round 2 (v0.27.64): which card has the keys.**

- **The survey.** With three cards on screen nothing said which one the keys reach: while a
  reply is written every key is the box's, and otherwise the mail's (or the list's). The
  cards' edges were all one colour.
- **The card the keys go to wears a stronger edge** (`cards::keyed_edge`): half way from a
  resting edge to the ink, darker on the light page, brighter on glass. The box while a reply
  is written, the mail while one is read, the list on its own, the setup page. It is never
  the pane's own focused stroke, which the gradient ring and the glow repaint wherever they
  find it.
- **Tests:** the mail's edge is the keyed one while reading and the box's while writing, the
  others rest, and the keyed colour is not the pane's stroke.

**Round 3 (v0.27.65): a copy keeps to its card.**

- **The survey** (the code behind a mouse drag). A drag over a non-terminal pane copies the
  cells as drawn (`gridsel::selection_text` over `pane.cells`), whole rows between its ends.
  Since the cards, a few lines of a mail copied with `│` at both ends of every line, and in
  the split view with the list's words from the same rows.
- **A drag copies the inside of the card it began in** (`InboxPane::copy_cells`, which
  `select.rs` asks for an inbox pane): no card's edge, nothing of the card beside it. A drag
  begun outside every card (the foot) copies as before.
- **Tests:** a drag down the mail in the split view copies its words, no `│` and nothing of
  the list, while the pane as drawn holds both.
