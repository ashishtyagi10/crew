# Loop — five UI, five AI, five inbox and todo rounds

**Status: IN PROGRESS (from v0.28.9).** Set by the user on 2026-10-22, after neon went dark
(v0.28.6), `auto` began obeying a pinned Mac (v0.28.7) and the file chooser hid its console
(v0.28.8): *"run 5 iteration of UI improvement, 5 AI improvement and 5 inbox and todo
improvement"*.

## Rules that hold every round

- **One round, one release.** Each ships through `scripts/release.sh` (which picks the version,
  gates `crew-app` plus the crates in `EXTRA`, merges `--no-ff`, tags and pushes main and the
  tag together). The rounds alternate UI → AI → inbox/todo, so no lane waits on another.
- **UI** rounds follow the shot surveys before them: everything but `/inbox` and `/todo`,
  judged on dark, light, neon and the glass family. Nothing new on screen without a shot.
- **AI** rounds follow `/improve` (`.superpowers/sdd/ai-loop-2026-09-14.md`): one harness
  feature each, smallest honest version, the changelog naming the tool the idea came from, a
  live probe where one is possible and "unit tests only" said plainly where it is not.
- **Inbox and todo** rounds follow the inbox loops' rules (`2026-10-22-inbox-loop-7.md`): no
  feature the user did not ask for; a round fixes, simplifies or polishes; nothing a test does
  opens a browser, reads the real Downloads, the real grant or the real Reminders.
- Every file stays under the 200-line cap and no file in `line-cap-debt.txt` grows; a test
  fails without each fix; no scratch file stays in the tree while `release.sh` runs (it
  commits with `git add -A`); `release.sh` prints `GATE FAILED` but exits 0, so its log is
  read for `RELEASED` before the next round starts.

## The survey (once, for all fifteen rounds)

Three at once: the UI on every palette through the headless shot tests; the AI harness
against the charter's open list and the 2026-10-20 "Next (AI)"; and the inbox and todo code,
newest first (the todo card, unread on top, the calendar, and the Reminders sync that has
never run on a real Mac).

## Log

**Round A1 (v0.28.9): a one-shot call is told not to think.**

- **The survey** found the reply judge's 30 s timeouts (2 of 5 on qwen3.8-max, 2026-10-20) were
  thinking: a call that does not stream never opted in, and qwen3.8-max now thinks on such calls
  by default, unbounded and unseen. Measured on the API with a judge-sized prompt: 211–292
  reasoning tokens and 7.3–9.5 s; told `enable_thinking: false`, 1.4–1.6 s and the same verdict.
- **Every non-streamed DashScope call says `enable_thinking: false`** (`crew-hive`
  `provider/thinking.rs`): the judges, the router, the ? command suggestion, commit messages and the planner. A
  model that only thinks refuses it and gets the one retry without (`openai_http`).
- **Live, the rename-and-test probe on qwen3.8-max** (swarm route): planning 24.1–24.8 s → 5.7–6.2 s,
  the judge after the last worker 30 s timeout / 3.8 s → 1.4–1.6 s, 3 of 3 verified.

**Round I1 (v0.28.10): a todo list that will not load never wipes Reminders.**

- **The survey** (the audit of the Reminders sync, which has never run on a real Mac): a
  `todos.toml` that will not parse (a write cut off by a crash, a field an older build cannot read)
  loads as no todos, and the sync's first pass at launch saw every pair's todo gone and its
  reminder unchanged, so it planned a delete for every reminder in the `crew` list, the last
  good copy. The guard covered Reminders answering empty, not crew.
- **The mirror guard** (`reminders/plan.rs`): when there are two or more pairs and every paired
  todo is gone at once, the pairs are forgotten and the open reminders come back as todos.
  The test fails without it.

**Round U1 (v0.28.11): a used hour outweighs an idle one on the heat grid.**

- **The survey** (every surface on every palette through the shot tests): on `/dash` and
  `/usage` an idle hour's dot outshone the quietest hour that saw use: on neon the dot stood
  2.8:1 and the used tile 1.5:1, on light 2.1:1 against 1.3:1, so the eye read the empty hours
  as the marks (queue J1, open since 2026-10-20).
- **One heat scale for both panes** (`plot/heatmap.rs` `heat_alpha`), its floor raised from a
  tenth to a half; the print pages' idle dot from 0.7 to half strength. Neon now 2.8 against
  4.3, light 1.6 against 2.5. Through see-through glass the dot keeps its desktop floor and the
  quietest tile reads 2.4:1 or more over a dark desktop. Not this round: over a white desktop
  `glass-clear`'s faintest tile is 1.2:1, a matter of that palette's gradient.

**Round I2 (v0.28.12): a title pairs only with one as done as it is.**

- **The survey**: an unpaired todo and reminder were paired by title alone, joined as done if
  either was. Every todo done before the sync was turned on stays unpaired for good, so a new
  "Pay rent" added on the phone was matched to last month's done "pay rent" and ticked off,
  and nothing showed in crew. The other way round, a crew todo was ticked by an old done
  reminder of the same name. A test asserted the merge.
- **A title pairs only when both sides agree on done** (`reminders/plan.rs`): each new one
  shows on the other side, nothing is ticked; two done ones of a name still pair, so turning
  the sync on twice makes nothing twice. The new tests (`plan_title_tests.rs`) fail without it.

**Round A2 (v0.28.13): the reply judge checks until it holds, and stops when nothing moves.**

- **Built in a second lane** (a worktree, `feat/a2-judge-loop`, by an implementer agent) and
  reviewed before it came across: `replyloop.rs`, a pure `step` and the loop. The judge sent a
  `not yet` back once and never read the revision; now each revision is judged, up to three
  checks, and it stops early with one `stopped checking — …` line when the judge names the same
  gap twice, or a revision ran no tool and answered as before. The lane's first cut stopped
  every tool-less revision unjudged, which would have cut off a gap in the words ("the files
  are not listed"); changed before release, with a test.
- **Live, three runs on qwen-max** (reply route, rename + doc comment + `cargo test`): two met at
  the first check. The third used the loop: tests failing → revised → passing; a new gap (the
  doc comment not shown by a tool) → the second revision ran out of its turn's tool budget
  mid-file and left the tests failing → `stopped checking — 3 checks used: … failed`. The stop
  line is honest; a revision can also go backwards, which is the per-turn tool budget's doing.

**Round U2 (v0.28.14): a theme chip is a whole square on its page.**

- **The survey**: the Theme field in `/settings` and the `/theme` picker drew a print palette as
  a half block, its accent over the top half and its page below. Where the accent matched the
  page it sat on, half the chip vanished: `dark`'s near-white accent on the light page left a
  black tooth (1.07:1 above it), and on neon `auto` was a lone white half (queue J7).
- **Every chip is now a whole square in its colour** (`swatch.rs` `chip_of`), on a cell of the
  palette's page for a print palette and alone on glass, as before. Shot on light and neon:
  `dark` and `auto` read as a black chip with a white square, `light` as a dark one on white.
  Still open: on the light page a glass palette's first chip (its near-white ink) is faint, as
  a glass chip carries no page by design (glass survey D-L10).
